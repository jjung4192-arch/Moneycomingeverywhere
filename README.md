# PhotoBridge — 전체 사진에서 골라 가져오기
Windows 10/11 x64용 아이폰 USB 사진 가져오기 시험판. 실제 iPhone USB 속도·미리보기 동작은 기기 검증이 필요합니다.

## 사용
Releases의 최신 ‘전체 사진 시험판’ ZIP을 받아 압축을 풀고 PhotoBridge.exe를 실행합니다. 런타임은 포함됩니다. 서명되지 않은 빌드가 차단되면 보안 기능을 끄지 마세요.

1. USB를 연결하고 아이폰을 잠금 해제·신뢰 승인합니다. 탐색기에서 iPhone에 접근할 수 있어야 합니다.
2. ‘아이폰 사진 불러오기’를 누르면 기기의 모든 사진 폴더를 자동으로 읽으며 목록을 계속 추가합니다. 페이지를 넘길 필요가 없습니다.
3. 스크롤하며 사진을 체크하고 저장 위치를 선택합니다.
4. ‘선택한 사진 가져오기’를 누릅니다. 목록 읽기가 진행 중이면 중지하고 현재 선택한 파일만 가져옵니다.

목록 읽기 중 ‘표시된 사진 전체 선택’은 그 시점까지 발견된 파일만 선택합니다. 아직 읽지 않은 사진까지 선택하는 기능은 아닙니다. 중지·접근 실패 시 전체 읽기가 완료되지 않았다는 상태를 표시하고 이미 표시된 목록은 유지합니다. USB는 iOS 사진 앱의 앨범 구성이 아닌 장치 폴더에 접근합니다. iCloud에만 있는 원본은 내려받아야 할 수 있습니다. 전송 형식은 아이폰 사진 설정의 ‘Mac 또는 PC로 전송 → 원본 유지’를 권장합니다.

## 변경한 병목
- 20개 페이지 UI 제거. 폴더를 한 번씩 열고 foreach 스트림으로 전체 사진을 자동 열거합니다. Items.Count와 같은 폴더 재조회, 파일마다 불필요한 크기·날짜 조회를 제거했습니다.
- 첫 결과부터 표시하며 내부 UI 갱신은 최대 32개 또는 150ms 단위로 묶습니다. 이 묶음은 표시 제한이 아니며 전체 목록이 하나의 스크롤 영역에 계속 추가됩니다.
- 썸네일은 현재 화면에 보이는 항목에만 요청합니다. 화면 밖 모든 사진의 썸네일을 미리 읽지 않습니다. 미리보기 메모리 캐시는 128장으로 제한합니다.
- 장치 객체를 다루는 STA와 실제 GetImage를 수행하는 별도 STA를 분리했습니다. COM 객체를 스레드 사이에 넘기지 않고 PIDL 바이트/파싱 경로만 넘겨 썸네일 STA에서 자체 Shell 객체를 만듭니다. 느린 썸네일 호출이 앱의 메타데이터·복사 작업줄을 붙잡지 않도록 했습니다.
- 원본 복사는 사용자가 가져오기를 누른 선택 목록에만 수행합니다. 원본 전체 사전 복사는 하지 않습니다. 선택한 파일의 크기·날짜는 그때 조회합니다.

이는 앱 측 병목 개선입니다. Windows 축소판 제공자가 장치 데이터를 읽거나 캐시할 수 있고, 물리 USB/기기 드라이버의 공유 자원 지연은 남습니다. 미지원 HEIC·동영상 등은 썸네일이 아닌 파일명으로 표시할 수 있습니다. 썸네일 COM 호출 하나가 멈추면 해당 썸네일 작업은 응답을 기다리지만 목록·선택 복사는 별도 작업줄에 있습니다.

## 안전성과 한계
아이폰 원본은 삭제하지 않습니다. 저장 폴더 `.photo-bridge/manifest.json` 기록과 PC SHA-256을 확인해 이미 완료한 복사본을 건너뜁니다. 동일 이름의 다른 파일은 덮어쓰지 않습니다. 바이트 단위 이어받기가 아닌 완료된 파일 단위 재시도입니다. 기기 원본 해시는 읽지 못하므로 크기 비교 및 PC 기록 검증이며 원본과 바이트 단위 일치를 보장하지 않습니다. 기기 경로/메타데이터가 바뀌면 식별에 제한이 있습니다. 중단 시 임시 파일이 남을 수 있고 파일당 10분 제한, 아이폰 한 대만 지원합니다. HEIC 변환·앨범/Live Photo 재구성·클라우드 업로드·계정 수집은 없습니다.

## 개발·검증
.NET 8 SDK. `dotnet run --project tests/PhotoBridge.Checks`로 공통 복사 검증. `dotnet build src/PhotoBridge.Windows`로 Windows 타깃 빌드.

Windows의 `PhotoBridge.exe --self-test`는 모의 기기로 전체 목록 350개 표시, 보이는 항목 위주 썸네일 요청, 맨 마지막 사진 선택과 스크롤 유지, 선택 파일만 복사, 목록 완료 전 선택, 인위적으로 멈춘 썸네일 중에도 복사가 가능한지를 확인합니다. 결과는 현재 디렉터리 ui-checks.txt. 실제 아이폰의 성능 테스트가 아닙니다. GitHub Actions는 이 검증과 Windows 창 시작이 통과한 뒤 ZIP 시험판을 배포합니다.
