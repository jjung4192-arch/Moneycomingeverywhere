# PhotoBridge — 보고 선택해서 PC로
Windows 10/11 x64용 아이폰 USB 사진 가져오기 시험판. **실제 iPhone/Windows USB 동작은 아직 기기 테스트 전입니다.**

## 사용
Releases의 최신 ‘사진 선택 시험판’에서 PhotoBridge-Windows-x64.zip을 내려받고 압축을 풀어 PhotoBridge.exe를 실행합니다. .NET 런타임은 포함됩니다. 서명되지 않은 빌드가 차단되면 보안 설정을 끄지 마세요.

1. USB 연결·아이폰 잠금 해제·신뢰 승인을 확인합니다. Windows 탐색기에 iPhone 사진이 보여야 합니다.
2. 앱의 ‘아이폰 열기’를 누르고 내부 저장소·DCIM 폴더를 두 번 클릭해 엽니다.
3. 사진을 체크합니다. 한 페이지 20개씩 읽으며 이전/다음 페이지로 이동해도 선택을 유지합니다. ‘이 페이지 선택’은 현재 보이는 파일만, ‘선택 해제’는 전체 선택을 해제합니다.
4. 저장 폴더를 정하고 ‘선택한 사진 가져오기’를 누릅니다. 선택한 파일만 가져옵니다.

아이폰 사진 설정에서 Mac 또는 PC로 전송을 ‘원본 유지’로 설정하는 것을 권장합니다. 자동 변환하면 파일 크기 검증이 실패할 수 있습니다. iCloud에만 있는 원본은 아이폰에서 먼저 내려받아야 할 수 있습니다.

## 빠르게 표시하는 구조
전체 폴더 재귀 스캔을 UI에서 제거했습니다. 사용자가 연 폴더를 20개씩 읽고 파일명·폴더 정보부터 표시합니다. 크기·수정 시각은 가져오기로 선택한 파일에 대해서만 조회합니다. 원본 CopyHere는 선택 후 복사 작업에서만 호출합니다. 사용자 선택을 모으는 동안 전체 원본을 PC로 사전 복사하지 않습니다.

Windows IShellItemImageFactory에 THUMBNAILONLY로 미리보기를 요청합니다. 축소판을 가져오는 과정에서 OS/드라이버가 표시용 데이터를 읽거나 캐시할 수 있으며, 내부 전송량을 앱이 보장할 수는 없습니다. 앱이 미리보기 원본 파일을 직접 복사하거나 저장하지는 않습니다. 미지원 형식·드라이버·HEIC 코덱·기기 상태에 따라 축소판 대신 파일명을 표시합니다. USB에서는 아이폰 사진 앱의 앨범 구성이 제공되지 않아 DCIM/장치 폴더 기준입니다. 목록/썸네일 요청 자체도 기기가 응답하지 않으면 느릴 수 있습니다. 현재 페이지 이후는 자동으로 전부 읽지 않습니다.

모든 Shell COM 객체는 하나의 STA 작업 스레드에서 생성·사용합니다. UI에는 문자열 ID와 이미지 복사본만 넘깁니다. 새 페이지로 이동하면 이전 축소판 요청은 중지하며, 늦게 도착한 결과는 현재 페이지를 덮어쓰지 않습니다. Windows의 단일 COM 호출이 응답하지 않는 동안에는 즉시 중지되지 않을 수 있습니다.

## 원본 보존과 이어받기
아이폰 원본을 삭제하지 않습니다. PC의 `.photo-bridge/manifest.json`에 완료 기록을 저장합니다. 같은 이름은 덮어쓰지 않고, 이미 완료한 복사본은 크기·PC SHA-256 확인 후 건너뜁니다. 선택하지 않은 파일은 가져오기 대상으로 보내지 않습니다. HEIC/JPG 변환이나 Live Photo/앨범 재구성은 하지 않습니다.

이어서 가져오기는 완료된 **파일 단위**이며, 파일 내부 바이트 단위 이어받기는 아닙니다. 원본 크기와 PC 크기를 비교하지만 기기 원본 해시를 읽지 못하므로 바이트 단위 일치를 보장하지 않습니다. 식별은 기기 경로·원본 폴더·이름·크기·수정 시각 기준이라 기기 경로 변경에 제한이 있습니다. 중단 시 임시 파일이 남을 수 있습니다. 파일당 10분 제한, 한 대 연결만 지원합니다. 계정·클라우드 업로드·분석 수집은 없습니다.

## 개발·검증
.NET 8 SDK. `dotnet run --project tests/PhotoBridge.Checks`는 공통 복사·중복·오류·중단·기록 검증. `dotnet build src/PhotoBridge.Windows`는 Windows 타깃 빌드입니다.

Windows에서 `PhotoBridge.exe --self-test`는 **모의 기기**로 실제 WinForms의 폴더 탐색·페이지 이동·선택 유지·선택 해제·선택한 1개만 복사되는지 확인합니다. 결과는 현재 디렉터리 `ui-checks.txt`에 기록합니다. 실제 USB 검증이 아닙니다. CI에서 공통 검증, 독립 실행 빌드, Windows 창 실행과 선택 UI 검증을 모두 통과해야 시험판을 배포합니다.
